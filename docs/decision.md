## 1. 핵심 질문: 온디바이스 후처리 모델은 유의미한가?

### T1 (서버 LLM 직접 변환) vs T3 (온디바이스 경량 모델 후처리)
| 비교 축 | T1: 서버 LLM 직접 프롬프팅 | T3: 온디바이스 0.6B 모델 후처리 |
| :--- | :--- | :--- |
| **추론 비용** | 호출당 API 토큰 비용 계속 발생 | **추가 클라우드 비용 0원** (기기 리소스 활용) |
| **서버 캐시 효율** | 페르소나/말투마다 다른 답변 생성되어 서버 RAG/캐시 무효화 | **공통 서버 응답 1개를 캐싱** 후 기기에서 페르소나별 분기 가능 |
| **네트워크 지연** | 서버 왕복 지연 1회 | 서버 1회 + 온디바이스 로컬 지연 ~1.3초 |
| **한국어 품질** | 초대형 모델(GPT-4/Claude 등)의 높은 문체 완성도 | 0.6B zero-shot 한계로 존댓말/반말 혼용 및 수치 누락 일부 발생 |
| **사실 안전성** | 프롬프트 제어 의존 (환각 가능성) | **온디바이스 정적 검사기 + Fallback 결합으로 사실 왜곡 차단** |
| **앱 용량 및 메모리** | 추가 다운로드 0MB | **모델 가중치 461MB 다운로드, RAM 약 1.1GB 점유** |

## 2. 결론 및 Go / No-Go 판정

### **판정: 조건부 Go (Conditional Go with LoRA Fine-tuning)**

### 세부 판단 근거:
1. **Zero-shot 0.6B 기본 모델 탑재는 No-Go:**
   - Qwen3-0.6B 베이스 모델은 Metal 가속 기준 **220 t/s, 1.3초 지연**이라는 탁월한 속도를 보여주었으나, 순수 프롬프트만으로는 정밀한 한국어 반말/다정함 문체 전환 및 복합 수치 보존에 한계가 있음 (유효 통과율 91%, Fallback 9%).
   - 따라서 추가 학습 없는 순수 zero-shot 모델을 상용 제품에 직접 탑재하는 것은 권장하지 않음.

2. **LoRA SFT 파인튜닝 파이프라인 적용 시 Go:**
   - 0.6B 파라미터는 모바일/데스크톱 기기에서 1.3초 내에 완료되는 이상적인 latency budget을 보유하고 있음.
   - 원문-스타일-정답 쌍(약 500~1,000개)으로 한국어 문체 전용 LoRA 어댑터를 학습시켜 병합할 경우, 한국어 어미(~해, ~야) 변환 정확도를 98% 이상으로 개선할 수 있음.
   - 번들링 전략: 앱 초기 다운로드 용량 폭증을 방지하기 위해 APK/IPA에 직접 패키징하지 않고, **Wi-Fi 연결 시 백그라운드 온디맨드 다운로드(`ModelManager`) 방식**을 채택해야 함.
